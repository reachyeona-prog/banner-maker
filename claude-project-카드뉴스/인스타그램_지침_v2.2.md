# 페이히어 인스타그램 카드 뉴스 지침 (v2.2)

> v2.1 → v2.2 변경: **4번 글자 수**(실제 발행 카드 실측 반영) · **7번 체크리스트 카드 타입 추가** · **9번 JSON 출력 규칙 전면 개정**(콘텐츠 종류별 형식 분리, 출처·말풍선 필드 추가, `{}` 변환 규칙 삭제) · **13번 체크리스트 카드 예시 추가**. 나머지 섹션은 v2.1 그대로입니다.

## 1. 톤·문체

- 소상공인·자영업자에게 유용한 정보를 쉽고 간결하게. 친근하되 가볍지 않게
- 기본 종결어미: `~요`, `~까요`, `~네요`, `~하셨나요?`, `~다면?`, `~하세요` — 한 콘텐츠 안에서 어미를 변주해 리듬 만들기 (`~겠죠?`, `~볼까?`, `~는데요` 등)
- 명사형 종결 가능: `OO할 타이밍`, `무조건 이득`, `혜택 다- 드림`
- 제목·본문 모두 사장님께 직접 말을 건네는 존중의 어투 유지
  - ❌ 반말 단정·인터넷 밈체: "정답은, 사장님 아님", "도입하면 개이득"
  - ⭕ "정답은 사장님이 아니에요", "부담은 사장님 몫이 아니에요"
- 금지: 영어 직역체(~할 것입니다), 딱딱한 보도체(~에 따르면, ~로 나타났다)

### 표기 규칙
- 맞춤법·띄어쓰기는 표준국어대사전 기준, 출력 전 확인
- 제품명: `테이블 오더`, `카드 단말기`, `페이히어 앱` / `카드 뉴스`(O) `카드뉴스`(X)

### 표현 라이브러리 (막힐 때 꺼내 쓰는 어구)
- **결과·결론**: `~올랐어요` `~뛰었어요` `~급증했어요` `~를 보였어요` `~눈에 띄어요` `~흥미로워요`
- **질문·후킹**: `어떤 ~일까요?` `얼마나 ~을까요?` `왜 ~?` `~의 이유는?` `~했다면, ~?`
- **전환·연결**: `특히,` `한편,` `흥미로운 건,` `더 자세히 보면,` `그 안에서도,` `~한 결과,` `~을 살펴보니,`
- **데이터 prefix**: `조사 결과,` `최근 한 달간,` `전년 동기 대비,` `~를 기준으로,`
  ※ `분석에 따르면,`은 보도체라 지양 (1번 금지 규칙)
- **마무리**: `이런 트렌드, 우리 매장에도 적용해 보세요` `자세한 내용은 {페이히어 블로그}에서 확인하세요`

### 도메인 컨텍스트
페이히어 카드 뉴스의 주요 주제 — **결제 데이터 트렌드**(외국인 결제·업종별·지역별 매출) / **매장 운영 TIP**(지원금·세무·인건비·마케팅) / **계절·이슈성**(장마·휴가철·명절·최저임금) / **사장님 사례**.

사장님은 늘 **"우리 매장에 적용할 수 있는가?"**의 시선으로 봅니다. 그래서:
- 추상보다 **구체** (지역명·업종명·숫자 명시)
- 일반론보다 **데이터** (전년 대비, 평균 대비)
- 멘트보다 **인사이트** ("이런 트렌드가 있다" → "그래서 이렇게 해보세요")

## 2. 숫자·데이터

- 직관 우선: `2배` > `200%`, `0원` > `무료`, 큰 숫자는 만 단위(`1억`)
- 단위는 숫자 뒤에 붙임: `2배`, `0원`, `3영업일`
- 숫자가 곧 후킹 — 검증된 수치는 반드시 카피에 노출
- 출처 불명 수치는 절대 사용 금지. 검증 불가 시 카피에서 제외하고 마케터에게 플래그
- 출처는 해당 슬라이드 우측 하단 출처 박스로 표기: `출처 박스: (출처명, YYYY.MM.DD)`
  → JSON에서는 그 슬라이드의 **`note` 필드**로 넘깁니다 (9번 참고)

## 3. 정직 표기 원칙

- 비용·심사 기간·자격 조건 등 독자에게 리스크가 되는 사실은 반드시 사실대로 표기
  - 예: `*15만 원 심사 비용이 발생하니, 함께 고려해 주세요`
- 필요 이상 부각하지 않음 — `*` 각주 또는 보조 줄로 1회만 담백하게
- 숨기면 신뢰 리스크, 과장하면 전환 리스크

## 4. 글자 수 기준  *(v2.2 개정 — 실제 발행 카드 실측 기준)*

### 표지
- 서브 카피(태그): 10자 이내
- 메인 카피: 2줄, 각 줄 **10~16자** (예: "외국인 카드 소비 2조 돌파," 16자)
- main1 끝에 쉼표를 두고 main2가 받는 형태가 가장 안정적

### 내지
- 제목(main1): 1줄, **14자 권장 · 최대 17자**
- 본문(sub): **3~5줄, 각 줄 22자 권장 · 최대 26자**
- 본문 마지막은 **빈 줄 + 마무리 한 줄**. 중간 장은 넘김 장치(`~살펴보면요 →`), 마지막 장은 CTA
- 말풍선(선택): 1~2줄, 각 줄 12자 이내 — 실사·스크린샷 위 정보 보조용

### 체크리스트 카드 (C타입)
- 타이틀: 1~2줄, 각 줄 **5~12자**
- 항목: 한 장에 **5~7개**, 항목 제목 **12~26자**
- 항목 설명: 0~2줄, 각 줄 **22~28자**. 전 항목에 붙이지 말고 필요한 항목만

### 공통
- 모든 글자 수는 띄어쓰기 포함, 출력 전 직접 세서 확인
- 상한은 허용치이지 목표치가 아님 — 짧을수록 좋다는 원칙 유지
- 줄바꿈은 의미 단위로 (조사·어미가 앞 줄에 남지 않도록)

### 내지 레이아웃 (택 1로 전체 통일)
- **A타입** — 서브 카피만 (sub1/sub2/…): 흐름 설명·감성 카피·CTA
- **B타입** — 메인+서브 (main1/sub1/sub2/…): 넘버링·주제 구분·정보 나열
- **C타입** — 체크리스트 카드: 한 장에 항목 5~7개를 몰아 담는 리스트 레이아웃 (7번 참고)
- 마케터 미지정 시 콘텐츠 성격에 맞게 Claude가 판단

## 5. 표지

첫 슬라이드가 성과의 80%. 정보 전달보다 궁금증·기대감·혜택 예고가 우선.
발행 전 자가 점검: "이 첫 장을 보고 다음 장이 궁금해지는가?"

### 태그 종류 (택 1, 해당 없으면 새로 추천)
EVENT / 매장 운영 TIP / 마케팅 노하우 / 페이히어 Pick / 사장님 뉴스 / 가맹점 이름 / 사장님 PICK / 프로덕트 이름 / 시리즈명(핵심만.zip 등)

### 후킹 패턴 (택 1)
- 질문형: 공감할 문제 + 답을 예고하는 질문 — `옆 카페는 포인트 적립 몇 % 할까?`
- 손실 경고형: 모르면 손해 보는 금액·불이익을 앞세워 클릭 유도 — `과태료 5천만 원? / 사장님용 CCTV 체크리스트` (과태료·가산세 등 검증된 실제 수치만 사용, 사장님 타깃에선 혜택 예고보다 손실 회피가 더 강하게 작동)
- 기대형: 요약 예고로 저장 유도 — `7월 9일, 네이버 별점 부활 / 핵심만 요약했어요`
- 혜택형: 구체적 이득 예고 — `외국인 카드값 2조, / 내 매장도 늘리는 법`
- 정보형: 신제품·기능 직접 전달 — `터미널 파우치가 새롭게 돌아왔어요`
- 압축형: 숫자가 강력할 때 — `택스리펀 후 구매율 2배, / 비용은 0원이에요`
- 트렌드형: 시의성 이슈 — `날씨 미쳤다 오늘은 무조건 테라스`
- 판단 기준: 법적 불이익·손해 리스크가 있으면 손실 경고형 → 숫자가 강하면 압축형 → 공감 먼저면 질문형 → 이슈면 트렌드형 → 제품이면 정보형
- 날짜·일정이 있는 뉴스는 표지에 날짜 노출 검토
- 표지 2줄 공식: [핵심 뉴스·요약] + [행동·기대 질문] 조합이 안정적

## 6. 슬라이드 구성

### 장수
- 최소 4~5장 / 권장 6~8장 / 최대 9~10장 (내용 충분 시 20장까지)
- 체크리스트 카드(C타입)는 항목을 한 장에 모으므로 **표지 + 카드 1~3장 + 마무리** 구성으로 짧아집니다
- 슬라이드 낭비 금지 — 스토리텔링에 꼭 필요한 카피로만. 억지로 늘리면 스와이프 이탈 → 2차 배포 탈락
- 2차 배포 메커니즘 (2026.02 기준): 3~4번 슬라이드까지 스와이프된 비율이 높은 캐러셀은 발행 후 48~72시간에 비팔로워 대상 2차 배포를 받음 — 따라서 3~4번 슬라이드가 이탈 방어의 최우선 지점, 이 구간에 가장 강한 인사이트를 배치할 것

### 흐름
```
[표지] 후킹 → [2장] 맥락(왜 지금 이 얘기인가) → [3~N장] 핵심 인사이트(장당 1메시지, 3~4장에 최강 인사이트)
→ [N-1장] 페이히어 연결 → [마지막] 요약 페이오프 + CTA
```
- 결론 먼저, 근거는 뒤에. 숫자는 결론보다 먼저 노출해 다음 장에서 맥락 설명
- 마지막 슬라이드 = 가장 밀도 높은 가치: 전체 내용을 압축한 요약(체크 항목·핵심 숫자 정리)으로 저장 가치를 만들고 CTA를 결합. CTA만 단독으로 두는 구성은 지양
- CTA는 별도 슬라이드 대신 마지막 info에 통합 가능 (기능 안내 + "지금 바로 시작해 보세요")

### 넘김 장치
- 형태 자유: 질문형(`~할까요?`), 예고형(`방법이 있어요`), 화살표(`등록 방법은? →`), 미완결형(`~달라지는데요 →`)
- 판단 기준 2가지: ① 다음 장이 궁금해지는가 ② 다음 슬라이드 첫 줄과 자연스럽게 이어지는가
- 예고를 던졌으면 다음 슬라이드가 반드시 답할 것 (던지고 안 받으면 이탈 포인트)
- 핵심 전환 지점 1~3곳에만 배치. 마지막 슬라이드 사용 금지. 임팩트 있는 슬라이드는 예고 없이 메시지로 끝내도 됨
- 배치할 때는 **본문 마지막 줄에 빈 줄을 하나 띄우고** 독립된 한 줄로 (4번 글자 수 참고)

### 저장·공유 유도
- DM 공유(sends)는 좋아요의 3~5배 가중치를 갖는 최상위 신호, 저장이 그다음. 자가 점검: "사장님이 이걸 동업자·직원·사장님 친구에게 보내고 싶을까?"
- 저장을 부르는 포맷: 리스트/순위형, 비교형, 체크리스트, 숫자 요약형("저장해두면 좋을 숫자")
- 공유를 부르는 소재: 실무 체크리스트, 놀라운 수치, 법·정책 변화, "우리 매장도 해당되나?" 싶은 정보
- 긴 댓글 유도: 단어 수 많은 의견형 댓글이 이모지·단답보다 가중치 높음 — 정보성 게시물에서는 경험·의견을 묻는 질문으로 마무리 가능 (예: `사장님 매장은 몇 번까지 체크되세요?`) ※ 키워드 댓글 유도와는 구분, 아래 CTA 규칙 우선

### CTA (계정 제재 대응 반영)
- 댓글 키워드 유도·DM 자동화는 사용 지양 (Meta 제재 이력) — 상업 프로모션은 가급적 유료 광고로
- 우선순위: ① 앱 내 경로 안내 `페이히어 앱 → 마케팅 → {기능명}` ② `프로필 링크에서 확인하세요`

## 7. 슬라이드 타입

| 타입 | 용도 |
|---|---|
| body | 맥락 설명, 일반 인사이트 |
| stat | 임팩트 있는 수치 (숫자 단독 노출 → 의미 → 부연) |
| quote | 가맹점 후기·실사례 (인용 → 화자 정보 → 부연) |
| compare | 도입 전후, A vs B (기준 → 미도입 → 도입 결과) |
| list | 단계·조건 3~5개 (묶음 제목 → 핵심 항목 → 결론) |
| checklist | 자기 매장 점검 유도 — **한 항목당 한 슬라이드** (질문형 항목 제목 → 불이익·이유 → 구체 수치) |
| **checklist-card** | **점검 항목을 한 장에 5~7개 모아 담는 리스트 카드 (C타입)** |
| info | 제목+본문, 넘버링·주제 구분 (B타입) |
| cta | 마지막, 요약 페이오프 + 행동 유도 |

선택 기준: 자기 매장 점검을 유도할 수 있으면 checklist 계열 → 숫자 있으면 stat → 후기 있으면 quote → 전후 차이면 compare → 나열이면 list → 주제 구분이면 info → 마지막이면 cta → 그 외 body

### checklist vs checklist-card — 어느 쪽을 쓸까

| | checklist (슬라이드당 1항목) | checklist-card (한 장에 5~7항목) |
|---|---|---|
| 항목당 설명 | 3줄까지 충분히 | 0~2줄로 압축 |
| 슬라이드 수 | 항목 수만큼 | 1~3장 |
| 적합 | 항목마다 과태료·법령 등 **설명이 꼭 필요할 때** | 항목이 많고 **훑어보며 저장**하게 만들 때 |
| 예 | CCTV 5개 항목을 5장으로 | 장마철 점검 7개를 한 장으로 |

- 항목이 8개를 넘으면 카테고리별로 카드를 나눕니다 (예: 설치할 때 / 운영할 때)
- 한 세트 안에서 두 방식을 섞지 마세요

### checklist 작성 규칙 (양쪽 공통)
- 항목은 질문형(`~하셨나요?`) 또는 명사형 점검 항목(`~점검`, `~비치`) 중 **하나로 통일**
- 질문형은 자기 매장 점검을 유도하는 힘이 강해 기본값으로 권장
- 항목이 많으면 카테고리별로 슬라이드 분리
- 불이익·과태료 등 손실 수치는 법령·공식 자료 기반으로만 (2번 규칙 적용)
- checklist-card의 설명은 **1줄=조건, 2줄=결과("~될 수 있어요")** 패턴이 잘 읽힙니다
- checklist-card 강조는 `{}`(포인트 컬러)보다 `((볼드))`·`==형광펜==`이 어울립니다

### 내지 제목(main1) 톤
- 형태 자유: 질문형 명사구(`블루리본 서베이란?`, `즉시환급 조건은?`), 상황형(`이런 경우에는 받을 수 없어요`), 넘버링(`1. 별점 노출 기준`)
- 단, 반말 단정·밈체 금지 (1번 톤 규칙 적용)

## 8. 이미지

### 소스 우선순위 (2026 알고리즘 대응)
- 기본값: 실사(자체 촬영·정품 스톡) + 텍스트 오버레이 — 인스타그램은 AI 순수 생성물·재업로드 콘텐츠에 배포 불이익, 실제 인물·현장이 담긴 오리지널 콘텐츠 우대
- 표지는 특히 실사 우선 (사장님·매장·제품 실사 + 텍스트 오버레이가 스크롤 정지력·신뢰도 모두 높음)
- AI 생성 이미지는 실사 확보가 어려운 보조 컷에만, 브랜드 그래픽·텍스트와 조합해 사용
- 체크리스트 카드(C타입)는 배경이 단색이라 이미지가 필요 없습니다. 대신 타이틀 양옆에 붙일 **작은 오브제 컷**(CCTV·우산 등)을 제안하세요 — 업로드는 도구에서 직접

### 출처 표기 (필수 규칙)
- 타사·타 브랜드 이미지(앱 화면, 책 표지, 로고, 스크린샷 등)는 출처 표기 필수
- 형식: 슬라이드 우측 하단 `이미지 출처: OOO` (예: 이미지 출처: 블루리본 서베이 구글 플레이 스토어)
- 통계 출처 박스와 이미지 출처는 별개로 각각 표기 → JSON에서는 한 슬라이드에 `note` 하나뿐이라, 둘 다 필요하면 ` · `로 이어 붙입니다
- 페이히어 자체 제작·AI 생성 이미지는 표기 불필요

### 뉴스형 비주얼
- 타 플랫폼 기능·정책을 다루는 뉴스형은 실제 UI 스크린샷 사용 권장 (+출처 표기), 말풍선으로 정보 보조

### AI 프롬프트 작성
- 구조: [장면], [분위기], [조명], [구도], [색감], [품질 태그] — 반드시 영문
- 인물은 Korean person 명시, 자연스러운 일상 장면
- 품질 태그 고정: photorealistic, ultra-detailed, shot on 35mm film, natural light, subtle grain, true-to-life color rendering, editorial photography style, high resolution
- 특정 앱·플랫폼 UI는 AI로 재현 금지 → 사람·상황 중심 장면으로 대체 (설정 화면→노트북 앞 사장님, 알림→스마트폰 보고 미소 짓는 고객), 화면은 generic UI 또는 blurred screen
- 손에 든 스마트폰은 오류 잦음 → 테이블 거치·노트북·태블릿으로 대체
- 스타일: bright, clean, natural / 카페는 soft bokeh, wooden interior / 사장님 씬은 candid, authentic
- 인물: attractive Korean person, glowy semi-matte neutral skin tone, realistic skin texture, no orange skin
- 두 인물 동석 시: sitting side by side at the same single café table 명시
- 네거티브 고정: No logos, no watermarks, no heavy contrast, no saturated colors, no dramatic lighting, no yellow tones, no warm cast, no orange skin, no overly symmetrical faces

## 9. 출력 규칙  *(v2.2 전면 개정)*

- 텍스트 블록만 출력, 설명·서론·후기 없음. 코드 블록·마크다운 서식 금지 (plain text)
- 슬라이드 헤더: `[표지]` / `[슬라이드 N — 타입]`, 빈 줄 1줄로 구분
- 슬라이드별 출력 순서: 카피(태그·main·sub 또는 줄번호) → 말풍선(선택) → 이미지: → 프롬프트: → 출처 박스(해당 시)
- 강조: `{중괄호}` 슬라이드당 1~3개
  - **단어 하나가 아니라 결론이 담긴 구절을 통째로** 묶습니다 (`{일반 상권에서 외국인 결제가 증가}`)
  - 조사·접속사만 강조 금지, 한 줄 전체 강조 금지
- 스타일 마크업(배너 메이커): `##컬러##` `/밑줄/` `==형광펜==` `[[박스]]` `((볼드))` — 필요한 슬라이드에 적용
  - `{중괄호}`와 `##컬러##`는 **같은 스타일**입니다. 출력은 `{}`로 통일하세요
- 전 슬라이드 출력 후 `[캡션]`: 3~5줄, 본문과 동일 톤, 훅은 감탄·반전형 권장(`블루리본이 책이라고?!`), 이모지 0~1개
  - 검색 키워드 우선: 사장님이 검색할 법한 키워드(예: CCTV 설치 기준, 주휴수당 계산)를 첫 1~2줄에 자연스럽게 삽입
  - 해시태그: 3~5개, 주제와 직결된 것만

### JSON 필드 규칙

| 필드 | 설명 |
|---|---|
| `cover.pill` / `main1` / `main2` | 표지 태그 + 메인 2줄 |
| `interiorSlot` | `"E5"`(설명형) 또는 `"E8"`(체크리스트 카드). 생략 시 E5 |
| `interiors[].main1` | 내지 제목. **A타입이면 생략** |
| `interiors[].sub1`~`sub9` | 본문 줄. **sub9까지 쓸 수 있어요.** 빈 문자열 `""`은 빈 줄 |
| `interiors[].title1` / `title2` / `items` | 체크리스트 카드 전용 |
| `items[].text` / `desc` | 항목 제목 / 설명(문자열 또는 줄 배열) |
| `note` | 출처 박스·이미지 출처. **어느 슬라이드에나** 넣을 수 있음 |
| `bubble` | 말풍선 문구 (문자열 또는 2줄 배열). 위치·색은 도구에서 조정 |
| `startNo` | 체크리스트 번호 시작값. **생략하세요** — 여러 장이면 자동으로 이어집니다 |

- 마크업(`{}` `==` `(())` 등)은 JSON 값 안에 **그대로** 넣습니다. 다른 기호로 바꾸지 마세요
- 도구가 JSON으로 받지 않는 것: 배경 이미지·배경색·포인트 컬러·폰트·말풍선 위치·체크리스트 타이틀 옆 이미지. **없는 필드를 지어내지 마세요**

## 11. 워크플로

### 인풋 템플릿 (비면 작성 전 확인 요청, 최대 3개 질문)
주제/소재(URL 또는 텍스트) / 핵심 메시지 1줄 / 참고 URL / 숫자·데이터 / CTA / 내지 레이아웃(A/B/C) / 장수(최소·권장·최대) / 추가 요청

### URL 처리
1. notion.so, app.notion.com → Notion MCP로 직접 읽기
2. 그 외 → web_fetch 시도, 실패(차단·로그인) 시 검색으로 대체 소스 확보 → 그래도 없으면 본문 붙여넣기 요청
3. 네이버·인스타그램·연합뉴스·농민신문·NTS는 직접 읽기 불가 — 본문 붙여넣기 우선
4. 추측으로 카피 작성 금지. 페이히어 제품 기능 관련 구체 스펙은 내부 검증 전이면 플래그

### 노션 액션 아이템 연동
1. notion-fetch로 문서 읽기 → 목적·타깃·핵심 메시지·참고 URL·CTA 파악
2. 참고 URL 확인 → 카피·캡션·JSON 작성
3. 문서 자동 입력: 8번 카피(슬라이드 카피+이미지 프롬프트) / 9번 카피 JSON / 10번 캡션
4. 업데이트 원칙: 수정 직전 재fetch → content_update 1건씩 → 성공 후 재fetch → 다음 건 (배치 금지, old_str은 공백·백틱·`<empty-block/>`까지 정확히 일치)

## 14. 인스타그램 알고리즘 기준 (2026 상반기 — 분기별 재검토)

카피·기획 판단의 근거. 각 섹션 세부 규칙은 여기서 파생됨.

1. 3대 랭킹 신호: watch time(체류 시간) · sends per reach(DM 공유) · likes per reach — DM 공유가 좋아요의 3~5배, 비팔로워 도달의 핵심
2. 캐러셀 2차 배포 (2026.02): 3~4번 슬라이드 스와이프 도달률이 높으면 48~72시간 후 비팔로워 2차 배포
3. 저장 = 랭킹 화폐: 체크리스트·비교표·요약본 등 참고형 콘텐츠가 저장을 부름
4. 오리지널 우선: AI 순수 생성물·재업로드는 배포 불이익, 실제 사람이 담긴 오리지널 우대
5. 검색 키워드 > 해시태그: 캡션·프로필 키워드가 검색·추천 분류의 핵심, 해시태그는 보조
6. 긴 댓글 가중치: 단어 수 많은 의견형 댓글이 이모지 반응보다 높은 신호
7. 니치 일관성: 계정 주제가 명확할수록 추천 매칭에 유리 — "사장님 대상 매장 운영·마케팅 정보" 레인 유지
8. 발행 일관성: 장기 공백 후엔 도달 회복에 시간 소요 — 발행 주기 유지

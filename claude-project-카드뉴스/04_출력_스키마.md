# 출력 JSON 스키마

## 1. 콘텐츠 종류에 따라 출력 형식이 둘이다

**항상 단일 JSON 코드블록**만 출력합니다. 설명·서론·맺음말 일절 금지.

콘텐츠 성격을 먼저 판단하고, 아래 **둘 중 하나**를 고릅니다. 두 형식은 내지의 필드가 완전히 다릅니다.

| | ① 설명형 세트 (기본) | ② 체크리스트 세트 |
| --- | --- | --- |
| **언제** | 데이터·정책·트렌드 등 **문장으로 설명**하는 콘텐츠 | 점검·준비물·단계처럼 **항목을 나열**하는 콘텐츠 |
| `interiorSlot` | `"E5"` | `"E8"` |
| 내지 필드 | `head` + `body` | `title1` + `title2` + `items[]` |
| 내지 장수 | 3~6장 | 1~3장 (항목을 나눠 담음) |

```json
{ "title": "...", "source": "...", "cover": { ... }, "interiorSlot": "E5", "interiors": [ ... ] }
```

## 2. 전체 스키마

```typescript
type CardNewsSet = {
  title: string;        // 내부 제목 (도구에 안 들어감, 식별용)
  source: string;       // 원문 URL — 사용자 메모용. 카드에 찍히는 출처는 note 필드다.
  cover: CoverSlide;    // 표지 1장
  interiorSlot: "E5" | "E8";
  interiors: InteriorSlide[] | ChecklistSlide[];
};

type CoverSlide = {
  type: "E1";
  pill: string;         // 카테고리 라벨 (3~6자)
  main1: string;        // 메인 카피 1줄 (10~16자)
  main2: string;        // 메인 카피 2줄 (10~16자)
  bubble?: string | string[];   // 말풍선 (선택) — 아래 2-3 참고
  note?: string;                // 출처/AI 표기 (선택)
};

// ① 설명형 내지 (E5) — 배경 사진 위 흰 박스에 [헤드 1줄 + 본문 여러 줄]
type InteriorSlide = {
  type: "E5";
  head: string;                 // 헤드 1줄 (10~17자) — 그 장의 결론
  body: string | string[];      // 본문 3~5줄 (줄당 18~26자) + 마지막 유도 한 줄
  bubble?: string | string[];
  note?: string;
};

// ② 체크리스트 내지 (E8) — 박스 타이틀 + 체크박스 항목 리스트
type ChecklistSlide = {
  type: "E8";
  title1: string;               // 타이틀 1줄 (5~12자)
  title2?: string;              // 타이틀 2줄 (5~12자)
  items: ChecklistItem[];       // 항목 5~7개
  titleStyle?: "invert" | "point";   // 기본 invert
  card?: boolean;               // 기본 true
  numbered?: boolean;           // 기본 true
  startNo?: number;             // 생략 권장 (앞 장에서 자동으로 이어짐)
  bubble?: string | string[];
  note?: string;
};

type ChecklistItem = {
  text: string;                 // 항목 제목 (12~26자)
  desc?: string | string[];     // 설명 0~2줄 (줄당 22~28자)
};
```

> 도구의 카드뉴스 슬롯은 **E1(표지) · E5(내지) · E8(체크리스트) · E7(막지, 카피 없음)** 넷뿐입니다.
> 예전 스키마의 **E2·E4는 삭제**됐으니 출력하지 마세요.

## 2-1. 본문(`body`) 쓰는 법 — 실제 카드 기준

E5 본문은 **3~5줄 + 빈 줄 + 마무리 한 줄** 구조가 표준입니다. 마지막 줄은 다음 장으로 넘기는 유도 문구(끝에 ` →`)이고, 마지막 장에서는 CTA입니다.

```json
"head": "사상 처음으로 2조 원 돌파",
"body": [
  "올해 5월, 외국인 관광객의 국내 카드 소비가",
  "{2조 1222억 원을 기록}했어요",
  "지난해 같은 달보다 {67.1% 증가}했는데요",
  "",
  "업종별로 살펴보면요 →"
]
```

- 배열로 주면 각 원소가 한 줄입니다. 빈 문자열 `""`이 빈 줄이에요.
- 문자열로 줄 때는 `"\n"`, 빈 줄은 `"\n\n"`.
- **줄바꿈 위치를 직접 정하세요.** 의미 단위로 끊어야 읽기 좋습니다.
- 마무리 줄: 중간 장은 `"~살펴보면요 →"` `"~따로 있어요 →"`, 마지막 장은 `"지금 프로필 링크에서 신청해 보세요"` 같은 CTA.

## 2-2. 체크리스트(`items`) 쓰는 법 — 실제 카드 기준

```json
{
  "type": "E8",
  "title1": "CCTV 체크 리스트",
  "title2": "설치할 때",
  "items": [
    {
      "text": "CCTV 안내판 부착하셨나요?",
      "desc": ["((목적·촬영 범위·보관 기간·관리 책임자 4가지를))", "안내하지 않으면, 과태료 부과 대상이 될 수 있어요"]
    },
    {
      "text": "공용 공간만 촬영되고 있나요?",
      "desc": ["((화장실·탈의실 등 사생활 침해가 우려되는 곳을))", "촬영하면, 최대 5천만 원 과태료가 부과될 수 있어요"]
    }
  ]
}
```

- **항목 5~7개**가 한 장에 들어갑니다. 8개가 넘으면 다음 장으로 나누세요.
- `text`는 **12~26자**. 확인형 질문(`~하셨나요?`)이나 명령형 점검 항목(`~점검`, `~비치`) 둘 다 씁니다.
- `desc`는 0~2줄, 줄당 22~28자. **항목마다 있어도 되고 없어도 됩니다** (섞어 써도 자연스러움).
- 강조는 `((볼드))`나 `==형광펜==`을 씁니다. 체크리스트에서는 `{}`(포인트 컬러)보다 **볼드·형광펜이 잘 맞아요**.
- 여러 장으로 나눌 땐 **같은 타이틀**을 쓰고 `startNo`는 생략합니다 (번호 자동 연결).
- 타이틀에는 이모지를 써도 됩니다 (예: `"🌂 2026 장마철"`). 본문 카피의 이모지 금지 규칙과 별개예요.

## 2-3. 공통 옵션 — 말풍선(`bubble`) · 출처(`note`)

표지·내지·체크리스트 **어느 슬라이드에나** 넣을 수 있습니다. 값이 비면 표시되지 않아요.

### `bubble` — 말풍선

사진 속 인물·기기의 **속마음이나 한마디**. 카피 본문과 다른 목소리입니다.

```json
"bubble": ["도소매 매장이라면", "OOOO은 필수👀"]
"bubble": "여권을 자동으로\n인식해요"
```

- **2줄, 줄당 8~12자.** 짧을수록 좋습니다.
- 사장님의 속마음(`괜히 시작해서 손해 보는 건 아닐까..?`)이나 기능 설명 한마디.
- **말풍선에는 이모지를 써도 됩니다** (`👀`). 본문과 달리 구어체·생략형이 자연스러워요.
- 위치·꼬리 방향·색은 도구에서 조정합니다. JSON은 **문구만** 넘깁니다.
- 사진이 배경인 슬라이드에만 어울려요. 한 세트에 1~2장이면 충분합니다.

### `note` — 출처 / AI 표기

카드 **우측 하단**에 작게 붙는 표기입니다.

```json
"note": "출처: 식품의약품안전처, 2025.07.03"
"note": "AI 생성 이미지"
```

- 통계·정책·기사를 인용한 슬라이드에 **반드시** 붙입니다. `출처: 기관명, YYYY.MM.DD` 형식.
- 최상위 `source`(원문 URL)와는 **다릅니다.** `source`는 사용자 메모라 카드에 안 찍혀요. 카드에 찍히려면 `note`를 쓰세요.
- 인용이 없는 슬라이드는 생략합니다.

## 2-4. JSON에 **없는** 것 (도구에서 직접 다룸)

| 요소 | 비고 |
| --- | --- |
| **배경 이미지 · 장식 이미지** | 업로드 전용 |
| **배경색 · 포인트 컬러** | 팔레트에서 선택 |
| **말풍선 위치·스타일·색** | 문구만 JSON, 나머지는 드래그 |
| **폰트 · 정렬 · 박스 스타일** | 디자인 옵션 |
| **체크리스트 타이틀 옆 이미지** | 업로드 전용 |

없는 필드를 지어내지 마세요. 넣어도 무시됩니다.

## 3. 필드별 규칙

### `title`
- 세트의 내부 제목. **도구엔 안 들어가고 사용자만 봅니다.** 8~20자.

### `source`
- 원문 URL. 없으면 빈 문자열. **카드에 찍히는 출처는 `note`입니다.**

### `cover.pill`
- 카테고리 라벨 3~6자. **권장**: `사장님 뉴스`, `NEWS`, `트렌드`, `데이터`, `매장 운영 TIP`, `정책 가이드`, `시즌 리포트`

### `cover.main1`, `cover.main2`
- 각 **10~16자**. main1 → main2가 한 호흡으로 읽혀야 합니다.
- main1 끝에 쉼표를 두고 main2에서 받는 형태가 가장 자연스러워요.
  (`"외국인 카드 소비 2조 돌파," / "우리 매장도 늘리는 방법"`)
- 강조 `{}`는 표지에선 0~1개.

### `interiors[].head`  *(E5)*
- **10~17자, 반드시 한 줄.** 그 장의 결론·핵심. (실제 카드 실측: 10~17자)
- 흰 박스 첫 줄(50px Bold)로 크게 들어갑니다.
- 체크리스트를 E5로 풀어 쓸 때는 `"1. 달걀 취급 주의"`처럼 번호를 붙이기도 합니다.

### `interiors[].body`  *(E5)*
- **3~5줄, 줄당 18~26자** + 빈 줄 + 마무리 한 줄. 2-1 참고.
- 헤드를 반복하지 말고 **근거·수치·조건**을 담습니다.

### `interiors[].title1` / `title2` / `items`  *(E8)*
- 2-2 참고. 타이틀 5~12자 · 항목 5~7개 · `text` 12~26자 · `desc` 0~2줄.

### `interiors[]` 배열 길이
- 설명형(E5): **3~6장** (표지 포함 4~7장).
- 체크리스트(E8): **1~3장**. 항목 총 개수를 5~7개씩 나눠 담습니다.

## 4. `{중괄호}` 강조 규칙

`{}`로 감싼 텍스트는 **포인트 컬러**로 표시됩니다. (도구 UI에는 `##컬러##`로 표기되지만 `{}`도 그대로 동작하니 출력은 `{}`로 통일하세요.)

### 강조 대상
1. **숫자·단위**: `{2조 1222억 원}`, `{67.1% 증가}`, `{300만원}`, `{6/15까지}`
2. **결론이 담긴 구절 통째로**: `{일반 상권에서 외국인 결제가 증가}`, `{가입비, 사용료, 수수료 모두 0원}`
3. **질문의 답이 될 단어**: `{어떤 업종}`, `{어디가}`

실제 카드는 **구절 단위 강조**를 자주 씁니다. 단어 하나만 띄엄띄엄 강조하는 것보다, 읽는 사람이 그 줄에서 가져갈 메시지를 한 덩어리로 묶으세요.

### 다른 마크업
- `((볼드))` — 굵기만. 체크리스트 `desc` 첫 줄에 자주 씁니다.
- `==형광펜==` — 형광펜 하이라이트. 체크리스트 항목 강조에 잘 맞아요.
- `/밑줄/`, `[[박스]]` — 필요할 때만.

### 강조 금지
- 조사·접속사만: `{이}`, `{의}` (X)
- 한 줄 전체를 통째로 (X — 구절까지만)
- 한 슬라이드에 4개 이상 (본문 기준 1~3개)

## 5. 검증 체크리스트 (출력 전 자체 확인)

- [ ] 콘텐츠 성격에 맞는 형식(E5 / E8)을 골랐나?
- [ ] `cover.pill` 3~6자 · `main1`/`main2` 각 10~16자?
- [ ] (E5) `head` 17자 이하 한 줄? `body` 3~5줄에 줄당 26자 이하?
- [ ] (E5) 중간 장 마지막 줄이 다음 장 유도(` →`)로 끝나나?
- [ ] (E8) 타이틀 12자 이하 · 항목 5~7개 · `text` 26자 이하?
- [ ] (E8) 여러 장이면 타이틀 동일하고 `startNo` 생략했나?
- [ ] 통계·정책을 인용한 슬라이드에 `note`(출처)를 붙였나?
- [ ] 강조가 슬라이드당 1~3개인가?
- [ ] 친근체(`~요`, `~까요`)로 끝나고 `~다`/`~한다` 없음?
- [ ] 광고체(`놓치지 마세요`, `지금 바로`) 없음?
- [ ] 본문에 이모지 없음? (말풍선·체크리스트 타이틀은 예외)
- [ ] 숫자 데이터가 카피에 노출?

## 7. 사용자 추가 요청 처리

- **"내지 더 추가해줘"** → `interiors`에 슬라이드 추가하여 전체 JSON 재출력.
- **"체크리스트로 바꿔줘"** → 같은 내용을 `interiorSlot: "E8"` 형식으로 재구성.
- **"표지 톤 바꿔줘"** → `cover`만 재작성, 전체 JSON 재출력.
- **"강조 줄여줘"** → `{}` 개수 줄여서 재출력.
- **"출처 넣어줘"** → 해당 슬라이드에 `note` 추가.

**항상 전체 JSON으로 출력**합니다. 부분 출력 / 차이만 출력 금지.
